# 变现策略：八周行动路线

| 项 | 内容 |
|---|---|
| 制定日期 | 2026-09-20 |
| 适用对象 | 本项目（`ai_agent_project`）的作者本人 |
| 目标档位 | 28K ~ 45K（一线 / 新一线，AI 应用层岗位） |
| 核心原则 | 每个学习动作都必须产出一个可卖的出货物；先出货，用反馈决定补什么 |
| 文档状态 | 待执行（Phase 0 未开工） |

> 关于本文所有薪资区间：**这是我的判断，不是承诺**。唯一的真实报价来自面试官，所以策略的核心动作是尽早拿到那个报价。

---

## 一、为什么是这个策略

三个变量的乘积决定你值多少钱，而不是「理解深度」这一个变量：

```
薪资 = 场景规模 x 呈现可信度 x 稀缺度（当前窗口）
```

| 变量 | 含义 |
|---|---|
| 场景规模 | 这套能力卖到什么公司（见薪酬矩阵） |
| 呈现可信度 | 能不能让面试官相信你真的做过（本文大部分动作都在解决这个） |
| 稀缺度 | 2026 年懂 Agent 工程治理的人相对少，红利期约还有 12~18 个月 |

### 1.1 认知前提：理解是门票，不是定价

| 你的投入 | 市场给的回报 | 备注 |
|---|---|---|
| 我知道它怎么跑 | 有资格谈这个岗位 | 不值钱，但没有就免谈 |
| 我知道为什么这么设计 | +5~8K | 能扛住追问，不被打穿 |
| 我能察觉不足 | +5~10K | P6/P7 分水岭，但有前提（见 1.2） |
| 能用这套判断解决新问题 | 换战场才有 | 同一个项目里加不出来 |

### 1.2 「察觉不足」怎么变现（最容易踩的坑）

同样是发现自己项目的短板，两种说法差 10K：

| 说法 A（减分） | 说法 B（加分） |
|---|---|
| 「这个项目 RBAC 有坑，粒度不够」 | 「当时的取舍是一次鉴权覆盖 90% 场景，剩下 10% 用 retry 兜；后来发现行级隔离在跨部门会漏，重做我会把 ACL 下沉到 SQL 层」 |
| 「我发现了三个 bug」 | 「工具重复调用导致 ReAct 跑满 10 轮，P50 从 7.1s 拖到 14s，我用两层收敛（registry 回传结果 + 循环层强制刹车）压回 7.1s」 |

**规律**：把不足讲成「当时条件下的决策 + 现在会怎么改 + 为什么」，是判断力；讲成「我有 bug」，是坦白。面试官对前者加薪，对后者打问号。

### 1.3 薪酬矩阵：理解深度 x 场景

| 理解深度 | 传统公司 AI 岗 | AI 创业公司核心链路 | 大厂 Agent 平台 |
|---|---|---|---|
| 只会跑通 demo | 15~20K | 15~22K | 进不去 |
| 搞懂原理 + 能讲取舍 | 22~30K | 25~35K | 30~40K |
| 再加排障量化 + 上线锚点 | 28~35K | 32~45K | 40~55K |
| 再加察觉不足 + 改进方案 | 35~45K | 40~55K | 50~70K |

**结论**：「demo 能跑」到「能讲清为什么」之间隔着 8~10K，这段差距四周就能补上，不需要再学新东西。

## 二、现状盘点：你现在有什么弹药

### 2.1 已具备（可直接开价）

| 资产 | 稀缺度评估 |
|---|---|
| ReAct + LangGraph 状态机 | 不稀缺，是门票 |
| MySQL RBAC + 数据脱敏 + 审批流 | 企业级才有（+3~5K） |
| token 按部门出账（`sys_llm_usage`） | 直击老板最关心的成本（+3~5K） |
| Milvus（RAG）+ PG-vector（记忆）双库并存 | 能讲清「为什么不是一个库」就是判断力 |
| SSE 流式 + per-user 限流 | 工程完整性 |
| 压测脚本（多 Key 轮换 + 429 拆口径） | 有度量意识 |
| **三个真实排障案例** | **最值钱（+5~8K）**，区分「写过」和「上线过」的唯一证据 |
| Docker Compose 全栈编排 | 部署完整性 |

### 2.2 卡住你的短板（按扣分严重程度排序）

| # | 短板 | 面试怎么戳穿你 | 补救动作 | 优先级 |
|---|---|---|---|---|
| 1 | 没人真正用（无日活、无真实场景） | 「上线了吗？多少人在用？」 | README + 一键 compose + 30 秒 GIF | P0 |
| 2 | MCP / multiagent / multimodal 是空壳 | 「这块做了吗？」一查就穿 | 删掉或在 README 标注「骨架未实现」 | P0 |
| 3 | 缺 `DEEPSEEK_API_KEY`、记忆保存异常未修 | 「这个报错你怎么处理？」 | 直接修掉 | P1 |
| 4 | 提交历史混乱（大量未跟踪文件） | 一般不看，但干净历史是加分 | `git add -A && git commit` | P1 |
| 5 | 无评测体系 | 「效果怎么保证？」 | 视面试反馈决定要不要补 | P2 |

> 注意第 2 条：**主动标注 TODO 是诚实，被发现是空壳是欺骗**。两者的分差 5K 起。

## 三、策略总览：双轨出货

```
现在 ─────────────────────────────────────────────→ 八周后

轨道 A（卖）  混乱的仓库 → 可演示产品 → 面试弹药 → 真实报价
                  ↑            ↑            ↑          ↑
               第1周       第2-3周      第4-6周     拿到数字
                                                       │
轨道 B（练）                    ┌──── 用 A 的反馈反向决定 ────┐
                               ↓                             ↓
                        补真短板（不是假想的）          第二个战场
```

**唯一不能颠倒的规则**：轨道 A 必须先走一周，再让 B 启动。因为 B 的输入必须是 A 的反馈，而不是你的猜测。

整个策略的核心两句话：

1. 变现优先于加深
2. 反馈优先于想象

你现在最大的风险不是不够强，而是继续加深六个月，最后发现自己补的东西市场根本不问。

## 四、Phase 0（第 1 周）：把仓库变成「能卖的资产」

**目标**：一个陌生人 clone 下来，10 分钟内能跑起来看完效果。

### 4.1 出货物与验收标准

| 出货物 | 验收标准（必须可当场验证） |
|---|---|
| README（架构图 + 一键启动 + 能力清单） | 用手机自己看一遍，能否 2 分钟说清「它解决什么问题」 |
| `docker compose up` 真能起 | **换一台机器或删掉容器重跑**，必须一次通过 |
| 30 秒 GIF：RBAC 鉴权拒绝 + Agent 流式回答 | 录屏，不加滤镜，看清关键交互即可 |
| 修掉已知坑（缺 Key、记忆异常、compose 账号） | 能完整跑通一轮带工具的对话 |
| MCP / multimodal 空壳处理 | 删掉，或在 README 明确标注「骨架，未实现」 |
| 提交历史清理 | `git status` 干净，语义化中文 commit message |

### 4.2 本周明确砍掉的

- 不许学新知识点
- 不许重构任何运行正常的代码
- 不许新增任何功能

### 4.3 为什么这周排第一

30~45K 那档的定价锚点，是面试官判断「这是个工具」还是「这是个作业」。同样的代码，仅靠 README + GIF 就能拉开 5~8K，这是全部动作里投入产出比最高的一个。

## 五、Phase 1（第 2-3 周）：把经验变成「弹药」

**目标**：4 个决策故事 + 1 份简历。每个故事能连讲 3 分钟，且经得起三轮追问。

### 5.1 四个决策故事（素材已全部具备）

| # | 故事 | 现象（证据） | 根因 | 修复 | 最可能被追问的取舍点 |
|---|---|---|---|---|---|
| 1 | 静默全失败 | 压测 28/28 成功，日志里却全是报错 | 缺 `model` 字段导致模型自主中断，却被判定为成功 | 回传成功信号 + `tools='none'` | 为什么不做全量成本上报？ |
| 2 | ReAct 死循环 | P50 从 7.1s 涨到 14s | 工具重复调用跑满 10 轮上限 | registry 回传结果 + 循环层强制刹车 | 为什么改 Prompt 而不是换框架实现？ |
| 3 | 度量失真 | 报出「错误率 20%」的误导结论 | 429 限流被混进错误率 | 拆成 `throttled` / `real_err` 双口径 | 为什么不给压测 Key 做限流豁免？ |
| 4 | 双库并存 | Milvus + PG 同时存在 | RAG 语义召回与记忆检索模式不同 | 各司其职 | 为什么不用一个库搞定？ |

### 5.2 简历句式（必须先定下来）

固定模板，每句话都必须满足三段式：

```
做了什么 → 用数字证明 → 解决了什么问题
```

| 反例（会被当背八股） | 正例（有证据） |
|---|---|
| 使用 LangGraph 实现 ReAct Agent | 基于 LangGraph 实现 ReAct 循环，通过工具结果回传 + 最大轮次双保险，将重复调用导致的 P50 从 14s 降至 7.1s |

### 5.3 验收标准

- 每个故事能在 3 分钟内讲完，且经得起三轮追问（需为每个故事准备追问预测清单）
- 简历上每条描述都包含一个具体数字
- **反向检查**：简历里任何一个数字，被追问时都要能说出测量方式

## 六、Phase 2（第 4-6 周）：拿真实报价

**目标**：尽早接触市场，用真实反馈校准定位。这步是整个策略里最被低估的一步。

```
投 15~20 家（分布在三档）
        ↓
┌────────────────┬──────────────────┬────────────────┐
│ 简历没回音      │ 面试总挂同一点    │ 顺利过         │
│ = 定位/包装问题 │ = 唯一的真短板    │ = 定价低了     │
│ → 改简历，不补能力│ → 只补这一点      │ → 往上抬 5K    │
└────────────────┴──────────────────┴────────────────┘
```

### 6.1 三档投递分布

| 档位 | 数量 | 目的 |
|---|---|---|
| 保底（传统公司 AI 岗） | 6 家 | 练手 + 拿底薪参照线 |
| 目标（AI 创业公司 / 中厂 Agent 岗） | 8 家 | **主战场**，争取主报价 |
| 冲刺（大厂 Agent 平台团队） | 6 家 | 校准上限，摸清差距 |

### 6.2 关键心态

不要「准备好再去」。本文所有区间都是猜测，**面试官的出价是唯一的真实报价**。第 4 周就去面，哪怕挂，也比在家多学一个月值：挂了能拿反馈，在家学拿不到。

## 七、Phase 3（第 5-8 周，并行）：由反馈驱动的补强

**原则**：Phase 2 的反馈决定这四周做什么。没有反馈支撑的东西，不许补。

| 如果市场反复问… | 就补这个 | 绝对不要补这个 |
|---|---|---|
| 「高并发怎么扛」 | 压测拉到 200 并发 + 连接池调优 + 排队策略 | 别去学 Kubernetes |
| 「企业级能力呢」 | RBAC 下沉到行级 + 审批流补齐 | 别去学模型微调 |
| 「效果怎么保证」 | 加评测集 + bad case 回归 | 别去学多模态 |
| 「成本怎么控制」 | 完善 token 计费 + 预算熔断 | 什么都别补，多面几家抬价 |
| 已经在谈薪了 | 停止补短板，专注比价 | 什么都别补 |

### 7.1 同时启动第二个战场（占 20% 时间）

下一个项目必须满足以下三选一：

```
[ ] 高并发（有真实的并发量压力）
[ ] 多租户（租户间数据 / 配额隔离）
[ ] 评测体系（有量化的效果度量）
```

**理由**：本项目的天花板就在第二档。它没有高并发、没有分布式、没有多租户隔离，继续加深加不出下一档，换战场才能继续往上。

## 九、红线：触发就立刻调转策略

| # | 触发条件 | 说明什么 | 立即动作 |
|---|---|---|---|
| 1 | 连续 3 家简历没回音 | 简历 / 定位问题，不是能力问题 | 暂停一切学习，重做简历 |

## 附录 A：决策故事速查（面试现场用）

每个故事按这五步讲，不要跳步：

```
现象（带数字） → 定位方法 → 根因 → 修复方案 → 当时的取舍 / 现在会怎么改
```

| 故事 | 一句话版本 | 必须背出的数字 |
|---|---|---|
| 静默全失败 | 模型缺字段自主中断，却被当成成功上报 | 28/28 成功但 0 次工具调用真实执行 |
| ReAct 死循环 | 重复调用工具跑满最大轮次 | P50 14s → 7.1s |
| 度量失真 | 限流被算成错误 | 错误率从「20%」拆成 429 与真实错误双口径 |
| 双库并存 | 检索模式不同，一个库搞不定 | Milvus 负责 RAG，PG-vector 负责记忆 |

> **最后一步最容易漏**：讲完修复必须补一句「如果重做我会……」。没有这句，你只是在汇报 bug；有了这句，才是在展示判断力。
