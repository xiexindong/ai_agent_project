> `tool_choice="auto"` = 调不调工具完全由模型决定，项目硬约束。

### 3.4 ⚠️ 一个值得注意的实现细节

`react_agent.py:187` 调用 `get_openai_tools_schema()` **不传 `user_level`**，而 `tool_registry.py:111` 的默认分支是：

```111:112:modules/tools/tool_registry.py
            if user_level == "normal" and tool.tool_type == "mcp":
                continue
```

即 **MCP 远程工具（`web_search` / `get_current_time` / `knowledge_stats`）默认不会进入发给模型的工具清单**，只有本地 `calculator` / `data_query` 会被模型看到。想让模型能用 MCP 工具，需要在这里传入 `user_level="advanced"` 或 `"admin"`。

## 四、阶段 3：条件路由（ReAct 的红绿灯）

```
graph.py:214  _should_continue(state)
    ├─ graph.py:237  state.finished == True                      → "answer"
    ├─ graph.py:239  need_tool_call 且 error 为空                 → "act"
    └─ graph.py:241  其他（含出错）                                → "answer"（兜底防死循环）
```

| 场景 | state | 返回值 | 下一跳 |
|---|---|---|---|
| 模型直接给答案 | `finished=True, final_answer="..."` | `answer` | answer 节点 |
| Prompt 注入被拦截 | `finished=True, error="prompt_injection_blocked"` | `answer` | answer 节点 |
| 模型要调工具 | `need_tool_call=True, action={name,args}` | `act` | act 节点 |
| 达到 10 次上限 | `need_tool_call` 被强制置 False | `answer` | answer 节点 |

## 五、阶段 4：act —— 工具执行（本地 / MCP）

### 5.1 调用链

```
graph.py:145  _act_node(state)
    └─ react_agent.py:238  act_step(agent_state)
        ├─ react_agent.py:252  tool_registry.execute_tool(name, params, session_id)   ★统一入口★
        ├─ react_agent.py:260  写日志 {name, arguments, result, success, duration_ms}
        ├─ react_agent.py:271  成功 → state.observation = str(result.result)
        │                      失败 → state.observation = "工具执行失败: {error}"  ← 错误回喂 LLM
        └─ react_agent.py:277  state.action = {}   清空，准备下一轮
    └─ 回写：observation / action / tool_calls_history / tool_call_logs
    └─ graph.py:97 固定边 act → reason（回到思考，形成循环）
```

### 5.2 `execute_tool` 的三道闸门（`tool_registry.py:116-189`）

```
tool_registry.py:158   ① 存在性检查    → 工具不存在：ToolResult(success=False, error="工具不存在: xxx")
tool_registry.py:163   ② 次数上限      → 单工具 >5 次："调用次数超限(5)，疑似死循环，已拦截"
tool_registry.py:171   ③ 相同参数去重  → "工具名:参数指纹" 已在本会话出现过则拒绝
tool_registry.py:181   ④ 真正执行      → tool.run(params)
tool_registry.py:185   ⑤ 记账          → _call_counts[name]++ ；_call_records[session_id].add(指纹)
```

被拦截时返回 `success=False` 的 **error 文本会作为 observation 回喂给 LLM**，模型读到"已超限/重复调用"后通常会转为直接作答。

三道死循环防线汇总：

| 层级 | 位置 | 上限 |
|---|---|---|
| 图级 | `graph.py:260 recursion_limit=30` | 30 次节点跳转 |
| 轮次级 | `react_agent.py:231 max_iterations=10` | 10 次 ReAct 循环 |
| 工具级 | `tool_registry.py:45 _max_calls_per_tool=5` | 单工具 5 次 |
