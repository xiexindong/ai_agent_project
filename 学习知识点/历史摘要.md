# 逐行拆解这段代码
```python
@staticmethod
def _format_context(long_term: list, short_term: list, query: str) -> str:
    """拼接记忆上下文为文本。"""
    blocks = []
    if long_term:
        blocks.append("【历史记忆摘要】")
        for item in long_term:
            blocks.append(f"- {item.get('summary', '')}")
    if short_term:
        blocks.append("\n【近期对话】")
        for item in short_term:
            blocks.append(f"用户: {item.get('query', '')}")
            blocks.append(f"AI: {item.get('answer', '')[:200]}")
    return "\n".join(blocks)
```

## 核心一句话
这个函数的作用：**把长期记忆、短期对话，拼装成一段纯文本，放进prompt里给大模型。这里有两处压缩策略**：
1. **long_term 长期记忆：只存 summary（摘要），不存原始长回答**
2. **short_term 近期对话：AI回答强制切片 `[:200]`，最多保留200个字符**

## 1. `long_term` 历史记忆摘要（长期记忆压缩）
```python
blocks.append(f"- {item.get('summary', '')}")
```
- long_term 来自**向量检索召回出来的片段**
- 存入向量库的时候，就已经提前生成了 `summary`（摘要）
- **不把原始完整问答放进来，只用精简摘要**
> 原始回答可能几千token，摘要几十~一两百字，大幅节省token。
> 代价：丢失细节，只保留核心要点。适合很久以前的历史，只需要“记得大概”。

## 2. `short_term` 里面 `item.get('answer', '')[:200]`（短期对话截断压缩）
```python
item.get('answer', '')[:200]
```
`[:200]`：**字符串切片，只取AI回答前200个字符，后面全部砍掉**。

举例：AI原本输出1000字长回答，这里只保留前200字符。
目的：
- 短期对话是最近几轮，本来就容易变长；
- 限制单轮回答长度，防止上下文token快速膨胀；
- 控制整体prompt总长度，**避免超出大模型上下文窗口上限**。

> ⚠️ 缺点：粗暴截断！如果关键信息刚好在200字符之后，会直接丢掉，大模型看不到后面内容。
> 这是最简单粗暴的压缩方案，工程原型常用；生产环境一般换成**摘要生成**而不是直接切片。

## 3. 结构区分（面试很容易问到）
```
【历史记忆摘要】
- 摘要1（向量召回的久远记忆，压缩成summary）
- 摘要2

【近期对话】
用户: xxx
AI: xxx（最多保留前200字符）
用户: xxx
AI: xxx（最多保留前200字符）
```
- 【历史记忆摘要】：**长期记忆，向量召回，用摘要压缩**
- 【近期对话】：**短期记忆，数据库取最近N轮，做字符截断**

> 把两类记忆分开区块，也是Prompt工程的设计：让大模型一眼区分「久远的参考记忆」和「刚刚连续对话」，防止混淆。

## 4. 整个函数的完整链路（串联你前面学的）
1. SQL查询chat_history → short_term（近期对话）
2. 向量检索 → long_term（历史摘要列表）
3. 调用 `_format_context`：
   - long_term 读取预先做好的summary
   - short_term里AI回答截断到200字符
   - 拼装成一段文本
4. 把拼装好的文本塞进System Prompt，作为背景资料给LLM

## 5. 三种记忆压缩方式对比（面试考点）
1. **预先摘要（long_term用的summary）**：对话结束后，异步调用LLM生成简短摘要存入DB/向量库。✅ 效果最好；成本是额外LLM调用。
2. **固定字符截断 [:200]（当前short_term）**：直接切字符串，**零成本**；缺点：可能切断关键信息。
3. **滑动窗口**：只保留最近N轮，更早对话直接丢弃（就是你之前SQL `LIMIT rounds`）。

## 6. 面试可以直接说的总结
> 这个 `_format_context` 是Prompt上下文组装函数，做了两层压缩：
> 长期记忆使用预生成的摘要summary，减少token；短期对话对AI的回答做字符截断，限制单轮长度。同时对记忆做区块分隔，方便大模型区分历史摘要和近期对话，控制整体prompt长度，防止超过上下文窗口。
