五道安检全部在 `modules/harness/middleware.py` 里。

## ① 一句话结论

`self.chain.run(req)` 就是把请求按固定顺序送过五道关卡——参数、权限、范围、限流、预算，任何一道拦下就止步返回，全过才放行。

## ② 五道安检的位置与分工

| 顺序 | 类 | 位置 | 查什么 | 拦截码 |
|---|---|---|---|---|
| 1 | `SchemaMiddleware` | middleware.py:62 | 参数对不对：缺必填、多未知参数、类型错 | `schema_invalid` |
| 2 | `PermissionMiddleware` | middleware.py:132 | 有没有资格：`principal.can("tool:xxx")` | `permission_denied` |
| 3 | `ScopeMiddleware` | middleware.py:160 | 越没越界：拿自己的身份查别人的部门/数据 | `scope_denied` |
| 4 | `RateLimitMiddleware` | middleware.py:208 | 调得猛不猛：令牌桶，全局桶 + 每人桶 | `rate_limited` |
| 5 | `BudgetMiddleware` | middleware.py:256 | 总量超没超：次数 / token / 墙钟三道闸 | `budget_exceeded` |

装配点在 `harness.py:561-572`：`MiddlewareChain([...])` 把五个按上面顺序串起来；执行点就是 `middleware.py:302` 的 `MiddlewareChain.run`——for 循环逐个 `check`，首个返回 `(code, reason)` 的直接 `block` 返回。

## ③ 输入 → 输出对照（以第 1 道为例，schema 要求 `expression` 必填 string）

```python
req.arguments = {"expr": "3*7"}              # 模型幻觉拼错了参数名
# chain.run(req) 逐道走：
#   SchemaMiddleware.check → ("schema_invalid", "缺少必填参数 ['expression']")
#   → 立即返回 ToolVerdict(allowed=False, code='schema_invalid', reason='缺少必填参数 [...]')
#   → 第 2~5 道根本不会执行

req.arguments = {"expression": "3*7"}        # 参数正常
#   SchemaMiddleware → None（放行）→ Permission → None → Scope → None
#   → RateLimit → None（扣 1 枚令牌）→ Budget → None
#   → 返回 ToolVerdict(allowed=True, action='allow')
```

## ④ 两个容易看漏的点

| 设计 | 原因 |
|---|---|
| 顺序 = 便宜在前：先查参数（纯内存比对）→ 最后动用全局资源（限流/预算） | 反过来先扣令牌再发现参数错了，等于白扣一枚令牌 |
| 中间件自己抛异常时按放行处理（middleware.py:306-310） | 沙箱/安检是加固项，一道关卡崩了不该让整条工具链路瘫痪 |

## 简单总结

1. 五道安检 = `middleware.py` 里的五个 `ToolMiddleware` 子类，`check` 返回 `None` 放行、返回 `(code, reason)` 拦截
2. 串联装配在 `harness.py:561-572`，执行就是 `chain.run` 的一个 for 循环（middleware.py:302-315），首个拦截即返回
3. 拦截码五种：`schema_invalid` / `permission_denied` / `scope_denied` / `rate_limited` / `budget_exceeded`，全带中文原因
