# 知识点 02：数据库写入那几行（execute + 占位符 + commit）

> 对应代码：`modules/memory/pg_manager.py:424-429`

## 一、一句话

这 5 行只干了一件事：**把 Python 的一个字典，塞进数据库某一行的某个格子里。**

```424:429:modules/memory/pg_manager.py
        self._reconnect_if_needed()
        self._cur.execute(
            "UPDATE chat_session SET agent_state = %s, updated_at = CURRENT_TIMESTAMP "
            "WHERE session_id = %s",
            (json.dumps(agent_state, ensure_ascii=False), session_id),
        )
        self._conn.commit()
```

## 二、先想象一张 Excel 表

`chat_session` 表长这样：

| session_id | user_id | title | agent_state | updated_at |
|---|---|---|---|---|
| abc123 | cli-user | CLI对话 | `{"iteration": 2, ...}` | 2026-09-15 10:30:00 |
| def456 | cli-user | 天气咨询 | `{}` | 2026-09-15 11:02:00 |

这段代码干的事：

> 找到 `session_id` 那列等于 `abc123` 的那一行 → 把它的 `agent_state` 格子擦掉重写 → 顺便把 `updated_at` 改成现在这个时刻

## 三、逐行拆开

### 第 1 行 `self._reconnect_if_needed()`

**先确认电话还通着。** 内部执行 `SELECT 1` 探活，断了就重连。

为什么要这行：数据库连接可能因为 PG 重启、空闲超时、网络抖动悄悄断掉。没有它，一次偶发断网就会让整个请求 500。（详见 `pg_manager.py:350` 的打电话类比）

### 第 2 行 `self._cur.execute(sql, params)`

⚠️ **注意是两个参数**，这是新手最容易迷糊的地方。

```python
execute(SQL语句, 要填进去的值)
```

| 参数 | 内容 | 特点 |
|---|---|---|
| 第 1 个 | SQL 模板，用 `%s` 挖坑 | 固定不变，只写一次 |
| 第 2 个 | 元组，按顺序填坑 | 每次调用都不一样 |

### 第 3-4 行：那个 SQL 到底在说什么

```sql
UPDATE chat_session              -- 改哪张表：chat_session
SET agent_state = %s,            -- 把 agent_state 这列改成 → 第1个坑
    updated_at = CURRENT_TIMESTAMP   -- 把 updated_at 改成 → 数据库当前时间
WHERE session_id = %s            -- 只改满足条件的行：session_id = 第2个坑
```

**`WHERE` 是命门**——没有它，表里**所有行**的 `agent_state` 都会被改成同一个值。生产事故排行榜第一名。

> 小知识：第 3、4 行是两个挨着的字符串，中间没 `+`。Python 会把相邻的字符串字面量**自动拼成一个**，纯粹为了换行好看，等价于写一行长 SQL。

### 第 5 行 `(json.dumps(...), session_id)`

填坑的值，是个元组，**顺序必须和 `%s` 出现的顺序一致**：

| 坑 | 值 | 说明 |
|---|---|---|
| 第 1 个 `%s` | `json.dumps(agent_state, ensure_ascii=False)` | 字典 → JSON 字符串 |
| 第 2 个 `%s` | `session_id` | 字符串，直接用 |

#### 为什么要 `json.dumps`？

数据库的 `agent_state` 列是 **JSONB 类型**，但 psycopg2（Python 的 PG 驱动）不认识 Python 的 `dict`，只认识字符串/数字。所以：

```python
{"iteration": 2, "finished": False}          # Python dict，驱动不认
        ↓ json.dumps
'{"iteration": 2, "finished": false}'        # JSON 字符串，驱动认
        ↓ PG 收到后自己解析
{"iteration": 2, "finished": false}          # 存成 JSONB
```

#### `ensure_ascii=False` 干嘛的？

```python
json.dumps({"query": "你好"})                      # '{"query": "\\u4f60\\u597d"}'  ← 默认转义
json.dumps({"query": "你好"}, ensure_ascii=False)  # '{"query": "你好"}'            ← 保持原样
```

不加的话，数据库里存的中文全是 `\u4f60\u597d` 这种，你用 SQL 查出来看不懂（虽然程序读回来能还原）。

### 第 6 行 `self._conn.commit()`

**提交事务 = 落盘生效。**

psycopg2 默认**不开 autocommit**，也就是：

```
execute()  →  改动只在本连接的事务里，别人看不见，磁盘也没写
commit()   →  真正写进去，别人能看见了
```

漏了会怎样：
- 函数返回看起来"成功了"
- 但连接一关，**事务回滚，改动全部消失**
- 更糟的是，未提交的事务**一直占着行锁**，别的请求改同一行会被卡住

> 📌 本项目每个写操作后面都紧跟 `commit()`（`save_turn`、`create_session`、`update_session_state` 都是），就是这个原因。

## 四、代入真实值走一遍

调用：

```python
pg.update_session_state("abc123", {"iteration": 2, "user_query": "3*7 等于多少"})
```

最终数据库收到的是（psycopg2 已把 `%s` 替换成安全转义后的值）：

```sql
UPDATE chat_session
SET agent_state = '{"iteration": 2, "user_query": "3*7 等于多少"}',
    updated_at = CURRENT_TIMESTAMP
WHERE session_id = 'abc123'
```

一行受影响。

## 五、三个必踩的坑

### 坑 1：`%s` 不是 Python 的字符串格式化

```python
# ❌ 千万别这么写（虽然语法上像）
cur.execute(sql % ("abc123"))

# ✅ 逗号隔开，交给驱动处理
cur.execute(sql, ("abc123",))
```

区别：**驱动会自动做转义**。手写拼接遇到用户输入 `'; DROP TABLE chat_session; --` 就直接被注入了。

### 坑 2：只有一个参数时别忘了逗号

```python
cur.execute(sql, (session_id))     # ❌ 这不是元组，是字符串！报错
cur.execute(sql, (session_id,))    # ✅ 逗号才是元组的灵魂
```

### 坑 3：JSONB 要传字符串，不能直接传 dict

```python
cur.execute("UPDATE t SET c = %s", ({"a": 1},))        # ❌ 驱动不认识 dict
cur.execute("UPDATE t SET c = %s", (json.dumps({"a": 1}),))  # ✅
```

（除非注册了 `psycopg2.extras.Json` 适配器，本项目没注册，所以统一 `json.dumps`。）

## 六、速查表

```python
cur.execute(sql模板, 元组参数)     # %s 按顺序被元组替换，自动转义
json.dumps(obj, ensure_ascii=False)  # dict → JSON 字符串，中文不转义
conn.commit()                        # 事务落盘，不调等于白改
WHERE 条件                           # 没有它就是全表更新（灾难）
CURRENT_TIMESTAMP                    # 让数据库自己取时间，避免应用服务器时区不一致
```

## 七、一句话带走

> `execute(模板, 值)` 分家写是为了**防注入**，`json.dumps` 是为了**让驱动认识 dict**，`commit()` 是为了**真的生效**。
> 三个动作缺一个，要么被黑、要么报错、要么改了个寂寞。
