## 一、能不能达到「AI Agent 开发工程师」要求？

**分层判断**：

| 目标级别 | 结论 | 理由 |
|---|---|---|
| 初级 / 应届 | **明显超出** | 多数初级候选人只做过 Demo，你有完整分层架构 + 协议层自研 |
| 中级（2–4 年） | **达标，且有两处超出** | 架构完整度、可靠性设计够用；自研 MCP 协议栈和提示词工程化是加分项 |
| 高级 / 资深 | **核心能力够，缺两块硬指标** | 缺①自动化评测与回归集 ②真实线上流量/成本/稳定性数据 |

**两处真正的亮点**（大多数人拿不出来）：

1. **自研 MCP 协议栈**，不是调 SDK — 你懂 `initialize`/`notifications/initialized` 两段握手、`tools/list` 与 `tools/call` 的区别、stdio 一行一帧、管道堵塞导致子进程卡死这类协议层细节。
2. **把提示词做成了独立工程层** — 模板注册表 + 版本 A/B + 变量强制校验 + token 预算裁剪 + 策略可切换。绝大多数候选人只是"写了几版提示词"。

**两个必须诚实面对的短板**（面试大概率被问穿）：

- **没有自动化评测体系**：你说"v2 比 v1 好"，凭什么？没有 eval 集、没有回归基线、没有 A/B 量化结果。这是高级岗的硬门槛。
- **没有生产数据**：没有 QPS、P95 延迟、单轮成本、可用率这类数字。简历上只能写"毫秒级/支持 N 个工具"这类设计指标，不能写线上指标。

## 六、补齐建议（按性价比排序）

**① 加一套最小评测集（最值得做，1–2 天）**
30–50 条问答，标注期望工具与关键结论；每次改提示词/改路由自动跑一遍，输出准确率、工具命中率、平均 token。简历上立刻能写"建立自动化回归评测，改动可量化验证"，这是高级岗的分水岭。

**② 补一份压测与成本报告**
并发 10/50 下的 P95 延迟、单轮平均 token 与成本、可用性。哪怕单机数据也能写。

**③ 把"实测发现 → 改提示词 → 效果验证"写成案例**
你项目里已经有现成素材（同一句 "3*7" 被连续调用 9 次，迭代提示词后收敛）。这类"发现问题→定位→修复→验证"的故事，面试官最爱听。

**④ 别写你讲不清的东西**
`多模态`、`多智能体`、`CrewAI` 如果你只是接了接口没深挖，就写"了解/接入"而非"精通"。

## 七、面试大概率被深挖的 5 个点（提前准备）

1. **为什么自研 MCP 而不用官方 SDK？** —— 讲 stdio 传输、握手两段式、管道堵塞、懒连接这些协议层理解
2. **Tool-RAG 为什么自己算余弦不用向量库？** —— 讲规模（几十条）、IVF_FLAT 近似 vs 全量精确、维度与模型版本耦合
3. **提示词缺变量为什么抛错而不是填空？** —— 讲"静默降质"是最难排查的故障
4. **token 超预算按什么顺序丢？** —— 讲权限 > 工具 > 观察 > 技能 > RAG > 记忆 > 工具历史，以及"半截上下文比没有更误导"的 50 token 阈值
5. **技能三级路由为什么这样分级？** —— 讲代价递增（字典 → 向量 → LLM）与降级链

这五个你都能讲清"为什么"，说明是真做过而不是抄的。
