## 一、这个项目是什么

一句话定位：**一个能查企业知识库、能记住历史对话、能调用工具的 ReAct 智能助手后端**。

用通俗的类比来理解：它像一个入职企业的新员工——

| 能力 | 类比 | 代码位置 |
| --- | --- | --- |
| 大脑（思考与决策） | 员工自己的判断力，决定"要不要查资料/用工具" | `modules/agent/` |
| 企业资料库（RAG） | 公司档案室，先粗查目录再精读文件 | `modules/rag/` |
| 记忆本 | 短期：手边便签（最近 3 轮原话）；长期：历年档案柜（摘要语义检索） | `modules/memory/` |
| 工具箱 | 桌上的计算器、业务查询机 | `modules/tools/` |
| 外部工具服务（MCP） | 打电话给别的部门（搜索组、报时组）办事，走标准话术 | `modules/mcp/` |
| 前台与门禁 | API 接口、工牌鉴权、权限分级、限流 | `modules/api/` |

五个核心子系统全部围绕一次对话运转，由 **LangGraph 状态图**统一编排。

## 二、技术栈速览

| 层次 | 选型 | 扮演的角色 | JavaScript 类比 |
| --- | --- | --- | --- |
| 对话大模型 | DeepSeek（OpenAI 兼容接口） | Function Calling 决策、生成答案/摘要 | 调用一个返回文本或工具调用的远程 API |
| Embedding | 智谱 embedding-2（1024 维） | 文档/摘要向量化，RAG 与记忆共用 | 把文字变成可算相似度的坐标数组 |
| Agent 编排 | LangGraph | 状态机：节点 + 条件边 + 循环 | 类似 Express 中间件管线，但支持回环和分支 |
| 静态知识库 | Milvus（IVF_FLAT + COSINE） | 存放文档分片向量 | 一个只存向量、擅长近似搜索的数据库 |
| 动态记忆库 | PostgreSQL + pgvector | 对话原文/摘要/向量/日志 + 业务表 | 普通关系库加了个"向量距离排序"索引 |
| 工具协议 | MCP（JSON-RPC 2.0 + stdio） | Agent 与外部工具进程解耦 | postMessage / RPC：两个进程按约定格式通信 |
| Web 服务 | FastAPI + uvicorn | REST 接口、依赖注入鉴权 | Express，路由 + middleware |
| 工程辅助 | loguru / pydantic / tenacity / tiktoken | 日志、配置校验、重试、token 计数 | winston / zod / retry 库 |

> 注意一个工程取舍：DeepSeek 官方没有 Embedding 接口，所以**对话用 DeepSeek、向量用智谱**，两家组合使用。

## 六、主干：一次提问的完整旅程

这是全项目最值得反复读的部分。入口在 [graph.py](ai_agent_project/modules/agent/graph.py) 的 `_build_graph()`，图共 **5 个节点、1 个条件分支**：

```
 ┌─────────┐    ┌────────┐  need_tool_call   ┌─────┐
 │ prepare │───▶│ reason │──────────────────▶│ act │
 └─────────┘    └───┬────┘                   └──┬──┘
                     │ 信息足够/达到轮次上限       │
                     ▼                           │
                ┌─────────┐    ┌──────┐         │
                │ answer  │───▶│ save │◀────────┘ (act 后回到 reason，形成循环)
                └─────────┘    └──────┘
```

### 节点 1：prepare —— 上阵前的准备（`react_agent.py` 的 `prepare_state`）

按顺序做五件事：

1. **Prompt 注入检测**：命中"忽略指令/假装你是/重置角色"等模式直接拦截返回（[validator.py](ai_agent_project/modules/common/validator.py) 的 `check_prompt_injection`）。
2. **输入清洗**：去控制字符、超长截断（5000 字）。
3. **Skill 技能匹配**：用触发词给每个技能算"意图证据分"（短语 0.6 / 双字词 0.4 / 单字 0.15，阈值 0.35），命中则把技能的 SOP 作业流程写入 `state.skill_context`，未命中留空走通用流程。
4. **记忆召回**：把问题向量化一次（这份向量会被复用，避免重复计费），然后从 PG 取"最近 3 轮原文 + 语义相似的历史摘要"，拼成上下文；超 4000 token 自动压缩。
5. **RAG 召回**：去 Milvus 查知识分片，经 BGE 精排后拼成知识上下文。

> 两个召回都包在 `try/except` 里：任何一个外部服务挂了，只置空上下文、记一条 warning，主流程继续。这就是"全链路降级"。

### 节点 2：reason —— 大脑决策（`reason_step`）

把【问题 + 知识 + 记忆 + 历史工具调用 + 可用工具清单】填入 Prompt，调用 DeepSeek 的**原生 Function Calling**（`llm.py` 的 `invoke_with_tools`）。模型只有两种输出：

- 返回 `tool_calls` → 置 `need_tool_call=True`，带着要调的工具名和参数进 act；
- 返回普通文本 → 直接当作最终答案。

模型返回的工具参数是字符串 JSON，代码会经 `repair_json()` 修复尾随逗号、单引号等常见格式问题。

### 条件边：`_should_continue`

三个判断：已完成 → answer；要调工具且无错误 → act；否则 → answer。

### 节点 3：act —— 执行工具（`act_step`）

不直接调用工具，而是交给 `ToolRegistry.execute_tool()` 统一调度（本地工具 or MCP 远程工具对上层透明）。结果写入 `state.observation`，并追加到调用日志，然后**边回到 reason**——模型看到观察结果后再决定继续调工具还是收尾。

### 防死循环的三道闸门

| 闸门 | 位置 | 规则 |
| --- | --- | --- |
| 轮次上限 | `reason_step` | `MAX_REACT_ITERATIONS=10`，达到后强制收尾给答案 |
| 单工具次数上限 | `tool_registry.py` | 每个工具每会话最多 5 次 |
| 相同参数去重 | `tool_registry.py` | 同一会话同一工具同一参数只执行一次 |
| LangGraph 保险 | `graph.run()` | `recursion_limit=30` 图级硬上限 |

### 节点 4：answer —— 生成答案与摘要（`generate_answer` + `generate_summary`）

产出两份文本：**完整详细答案**（含推理依据，要求末尾带【摘要】标签）和**一句话精简摘要**（优先正则提取标签，其次调 LLM 生成，短回答直接截断省 token）。

### 节点 5：save —— 落库（`graph.py` 的 `_save_node`）

- 摘要调一次 embedding，连同**原文 + 摘要 + 摘要向量 + 工具日志 + RAG 来源**写入 `chat_history`（即"三数据落库"：原文可溯源、摘要可投喂、向量可检索，缺一不可）；
- 把整个 AgentState 序列化进 `chat_session.agent_state`（JSONB），这是**断点续跑**的基础。

## 七、四大子系统深读

### 7.1 RAG：企业档案室（`modules/rag/`）

**入库链路**（命令：`python main.py ingest <文件>`）：

```
文件 ─▶ DocumentLoader ─▶ TextSplitter ─▶ EmbeddingService ─▶ Milvus
      TXT/MD/PDF      500字/片+80字重叠   智谱批量向量化      insert+flush
```

- [text_splitter.py](ai_agent_project/modules/rag/text_splitter.py) 用**递归分隔符**切分：先按段落 `\n\n`，切不开再退到句号、空格，最后才硬切；相邻分片把上一片尾部 80 字拼到下一片开头，保证语义不被切断。
- [vector_store.py](ai_agent_project/modules/rag/vector_store.py) 首次启动自动建集合：7 个字段（chunk_id 主键、content、source、embedding 等），索引为 `IVF_FLAT + COSINE`。

**检索链路（两阶段：粗召回 + 精排）**：

```
query ─▶ 智谱向量化 ─▶ Milvus COSINE 召回 top5 ─▶ 阈值0.65过滤 ─▶ BGE精排 ─▶ top3 拼上下文
```

- 粗排看向量距离，快但可能"形似神不似"；
- 精排 [reranker.py](ai_agent_project/modules/rag/reranker.py) 用 Cross-Encoder 逐对打分，更准。**BGE 模型没装时自动降级**：向量分 × 0.7 + 关键词命中率 × 0.3。
- 全部低于阈值或 Milvus 无结果时，`build_context()` 返回空字符串——Prompt 里明确"知识库无内容就如实告知"，从源头压制幻觉。

### 7.2 记忆系统：双层记忆（`modules/memory/`）

```
                    ┌─────────────────────────────┐
 提问时召回 ───────▶ │ 短期记忆：最近 3 轮完整原文    │ PG 按 created_at 倒序取
                    │ 长期记忆：摘要向量 top5        │ pgvector 余弦距离 <=> 排序
                    └──────────────┬──────────────┘
                                   │ 拼接后 > 4000 token？
                          是 ─▶ LLM 把多条旧摘要合并成一条全局摘要（压缩）
                          否 ─▶ 直接投喂
 回答后保存 ───────▶ 原文 + 摘要 + 摘要向量 写入 chat_history
```

两个值得学的细节：

1. **多用户隔离**：向量召回 SQL 带 `WHERE user_id = %s`，每个用户只能语义召回自己的历史（[pg_manager.py](ai_agent_project/modules/memory/pg_manager.py) 的 `search_memory_by_vector`，距离算子 `<=>`，相似度 = `1 - 距离`）。
2. **压缩不是删除**：`memory_manager.py` 的 `_compress_long_term` 只压缩投喂给 LLM 的上下文，数据库里的原文永远保留。

### 7.3 Agent 状态：一份结构走完全程（`state.py`）

`AgentState` 是个 26+ 字段的数据容器，分六组：会话信息、RAG 上下文、记忆上下文、ReAct 循环（iteration/action/observation/tool_call_logs）、任务编排（sub_tasks 预留）、输出（final_answer/llm_summary/summary_embedding）。

它同时提供 `to_dict()` / `from_dict()`：LangGraph 节点之间传 dict（`AgentStateDict` 是 TypedDict），业务代码里用 dataclass，落库时 JSON 序列化。**JavaScript 读者可把它类比成 Redux 的全局 store**：每个节点是一个 reducer，返回要更新的字段，LangGraph 负责合并。

### 7.4 工具体系：统一契约 + 适配器模式

**本地工具契约**（[base_tool.py](ai_agent_project/modules/tools/base_tool.py)）：所有工具实现 `name / description / parameters / execute()`，并自动获得：
- `to_openai_format()`：一键转成 OpenAI Function Calling 的 JSON Schema（给 LLM 看的"工具说明书"）；
- `run()` 模板方法：参数必填校验 → execute → 统一封装 `ToolResult(success, result, error, duration_ms)`，异常永不抛出调用方。

两个示例工具：
- [calculator.py](ai_agent_project/modules/tools/calculator.py)：**安全教科书**。没有用 `eval()`，而是用 `ast.parse` 解析成语法树，只允许白名单运算符（加减乘除幂取整）和白名单函数（sin/sqrt…），遇到属性访问、import 直接报错。
- [data_query.py](ai_agent_project/modules/tools/data_query.py)：内存字典模拟 users/orders/inventory 三张业务表，演示枚举参数和精确查询。

**MCP：用标准协议接外部工具**（`modules/mcp/`）。通信模型：

```
Agent 进程                          MCP Server 子进程
   │  stdin:  {"jsonrpc":"2.0","method":"initialize",...}  ───▶
   │  stdin:  notifications/initialized                     ───▶
   │  stdin:  tools/list                                    ───▶
   │ ◀── stdout: {"result":{"tools":[web_search, ...]}}
   │  stdin:  tools/call {name, arguments}                  ───▶
   │ ◀── stdout: {"result":{"content":[{"type":"text",...}]}}
```

- [protocol.py](ai_agent_project/modules/mcp/protocol.py) 是 JSON-RPC 2.0 的信封：`{jsonrpc, method, params, id}`，错误码沿用标准（-32601 方法不存在等）。
- [mcp_client.py](ai_agent_project/modules/mcp/mcp_client.py) 用 `subprocess.Popen` 拉起 server，通过 stdin/stdout 一行一条 JSON 通信；stderr 用后台线程单独读，防止管道堵塞。
- 关键设计是 **`MCPToolAdapter`**：MCP 工具被包装成和本地工具一样的接口（同名方法 `run / to_openai_format`），注册器和 Agent 完全不感知工具在本地还是远程——这就是**适配器模式**，类似前端把不同后端的响应统一包成同一种对象。
- Server 端（[mcp_server.py](ai_agent_project/modules/mcp/mcp_server.py)）提供 3 个工具：`web_search`（Tavily，没配 Key 会友好返回提示）、`get_current_time`、`knowledge_stats`。

### 7.5 技能系统：Skill 与 Function Call 如何协作（`modules/skills/`）

**两者是不同层级**：Function Call 是 LLM 每轮自由选择的**原子函数**；Skill 是系统在 ReAct 开始前按意图预选的**作业流程包**（触发词 + SOP 提示词 + 推荐工具集合）。类比：Function Call 像员工桌上的一件件工具，Skill 像领到任务后翻开的标准作业指导书（SOP），指导书会告诉他"这类事按 4 步做、优先用哪件工具"。

运行时协作链路：

```
用户提问 ─▶ SkillRegistry.match() 关键词证据打分（阈值0.35）
              │命中                          │未命中
              ▼                              ▼
   注入技能 SOP 到 reason prompt     通用助手提示
   （声明推荐工具 + 作业步骤）
              ▼
   reason 节点：LLM 读 SOP，仍通过 Function Calling 决定具体调哪个工具
```

4 个内置技能（[builtin_skills.py](ai_agent_project/modules/skills/builtin_skills.py)）：数学计算（绑 calculator）、企业数据查询（绑 data_query）、知识库问答（走 RAG 无函数工具）、联网检索（绑 MCP 的 web_search/get_current_time）。

设计要点：
- **软引导不硬限制**：技能只注入 SOP 和推荐工具，不屏蔽其他工具，避免误匹配导致无法作答；
- **防误命中**：单字弱词（如"加""除"）仅 0.15 分，"加个微信"不会激活计算技能；"今天好开心"不命中联网技能（触发词用"今天新闻"而非"今天"）；
- **可降级**：匹配异常只记 warning，按通用流程继续；
- **可扩展**：继承 `BaseSkill` 填类属性，加入 `get_default_skills()` 即完成注册。
- 调试命令：`python main.py skills` 查看清单，`python main.py skills -q "查一下订单状态"` 预览匹配结果。

### 7.6 API 层与企业级管控（`modules/api/`）

组件在 `APIServer.__init__` 中一次性装配（LLM、PG、Memory、工具、MCP、RAG、Agent 图），全部为单例，请求间复用。

**接口清单**：

| 方法路径 | 功能 | 权限 |
| --- | --- | --- |
| GET `/health` | 健康检查 | 无 |
| GET `/` | 前端页面 | 无 |
| POST `/chat` | 对话（自动建会话/校验会话归属） | 登录 |
| GET `/history/{id}` | 会话历史 | 登录 |
| POST `/knowledge/ingest` | 上传文档入库 | 管理员 |
| GET `/knowledge/stats` | 知识库统计 | 登录 |
| GET `/skills` | 技能清单及其绑定的函数工具 | 登录 |
| GET `/tools/logs` | 工具审计日志 | 高级用户 |
| GET `/reviews/pending` | 人工审核队列 | 管理员 |

**鉴权与权限**（[auth.py](ai_agent_project/modules/api/auth.py)）：
- 请求头 `X-API-Key` 换用户身份（演示用内存映射，生产换 JWT/OAuth）；
- 三级等级 normal < advanced < admin，`RequirePermission(level)` 是 FastAPI 依赖工厂——类比 Express 里一个校验中间件；
- 普通用户拿不到 MCP 工具的 schema（`tool_registry.get_openai_tools_schema` 按 level 过滤），**从源头让模型无法调用越权工具**；
- 限流用**滑动窗口**：每用户 60 秒 20 次，每次请求先清理窗口外时间戳再计数，超限返回 429。

## 八、横切机制（工程化亮点）

### 8.1 全链路降级地图

| 依赖出问题 | 降级策略 | 代码位置 |
| --- | --- | --- |
| MCP Server 启动失败 | 仅用本地工具，warning 后继续 | main.py / server.py 装配处 |
| Milvus 连不上 | RAG=None，纯模型+记忆对话 | 装配处 try/except |
| BGE 模型未安装 | 向量 0.7 + 关键词 0.3 加权精排 | reranker.py |
| RAG 召回为空/低分 | 返回空上下文，要求模型不编造 | rag_chain.py |
| 记忆服务异常 | 关闭长期记忆，空上下文继续 | react_agent.prepare_state |
| tiktoken 不可用 | 中文按 2 token、其他按 1.3 估算 | token_counter.py |
| embedding 某批次失败 | 零向量填充，不中断整批入库 | embedding_service.py |
| 结构化 JSON 解析失败 | 去代码块/去尾逗号/单引号修复，再不行普通调用兜底 | validator.py + llm.py |
| PG 断连 | 执行前 `SELECT 1` 探活，自动重连 | pg_manager.py |

统一由 [exceptions.py](ai_agent_project/modules/common/exceptions.py) 支撑：5 个异常子类（LLM/RAG/Tool/Memory/MCP）+ `@handle_exception(default, reraise)` 装饰器，非关键路径吞异常返回兜底值，关键路径（建会话、存记忆）重新抛出。

### 8.2 单例清单

`LLMClient`、`PGManager`、`MilvusVectorStore`、`EmbeddingService` 都用 `__new__` + 初始化标记实现单例，保证全进程只建一次连接池/客户端。`get_settings()` 则用 `@lru_cache` 缓存配置。

### 8.3 安全措施汇总

- 输入侧：Prompt 注入正则拦截、输入清洗与长度限制；
- 工具侧：计算器 AST 白名单沙箱、工具参数必填校验、重复调用/次数拦截；
- 接口侧：API Key、三级权限、会话归属校验（防越权看别人会话）、滑动窗口限流；
- 审计侧：`tool_call_log` 表记录每次工具调用的入参/出参/耗时/状态。

## 九、数据库表结构（PostgreSQL + pgvector）

```
chat_session（会话主表）
  session_id PK │ user_id │ title │ agent_state JSONB ◀── Agent状态断点续跑
        ▲ 1
        │ n（ON DELETE CASCADE）
chat_history（对话记忆表，核心）
  id PK │ session_id FK │ user_id │ user_query
        │ llm_full_answer（原文）│ llm_summary（摘要）
        │ summary_embedding vector(1024)  ◀── ivfflat 余弦索引
        │ tool_call_log JSONB │ rag_sources JSONB

tool_call_log   工具调用审计（session/用户/入参/出参/耗时）
review_queue    人工审核队列（pending/approved/rejected）
standard_answers 标准答案库（init_db.sql 中预留，审核沉淀反哺 Few-shot）
```

- 表结构在代码里**幂等自动创建**（`PGManager._init_tables`，启动即可用），[init_db.sql](ai_agent_project/init_db.sql) 供独立初始化/审阅，比代码多一张 `standard_answers`；
- 向量维度 1024 必须与智谱 embedding-2 一致，改模型时三处同步：`.env` 的 `EMBEDDING_DIMENSION`、Milvus 集合 dim、PG 的 `vector(1024)`。

## 十、如何跑起来

```bash
# 1. 安装依赖（Python >= 3.10）
```

## 十一、读代码时值得带走的知识点

1. **ReAct 模式**：Reason→Action→Observation 的循环本质，以及"用 Function Calling 替代正则解析动作"的现代写法。
2. **LangGraph 状态机**：节点、条件边、回环、recursion_limit；与普通链式调用的区别在于可循环、可分支、状态可持久化。
3. **RAG 两阶段检索**：向量粗召回 + Cross-Encoder 精排，以及 chunk overlap、相似度阈值、无结果不编造等工程细节。
4. **双向量库分工**：Milvus 管静态知识、pgvector 管动态记忆；为什么记忆要存"原文+摘要+向量"三份。
5. **上下文工程**：短期原文 + 长期摘要 + token 阈值触发 LLM 压缩。
6. **协议解耦思想**：MCP 的 JSON-RPC + stdio，适配器模式抹平本地/远程工具差异。
7. **生产级健壮性**：单例、重试（tenacity 指数退避）、降级矩阵、异常分层、滑动窗口限流、AST 沙箱、断点状态持久化。
