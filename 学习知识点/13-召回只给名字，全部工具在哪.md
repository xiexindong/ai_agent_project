# 召回只返回几个名字，全部工具在哪？

> 配套代码：`modules/agent/router.py`（L0 路由）、`modules/tools/tool_registry.py`（工具注册表）、`modules/mcp/gateway.py`（网关目录）
> 一句话结论：**召回不是数据来源，只是筛选器。全部工具一直在两个权威源里，召回只吐名字，拿到名字后再回查权威源取回完整工具。**

---

## 一、先说结论

| 问题 | 答案 |
|---|---|
| 语义召回返回的是什么？ | **只有工具名 + 分数**（`ToolHit(name, score, source)`） |
| 全部工具在哪？ | `ToolRegistry._tools`（本地实例）+ `gateway._tool_index`（远程目录） |
| 召回是在"部分"里挑吗？ | **不是**，是先合并出全量候选池，再在里面挑 |
| 拿到名字后怎么变成能用的工具？ | 本地 `get_tool(name)`；远程 `ensure_registered()` 回查目录 + 连 server + 包装注册 |
| 索引里为什么不存工具本体？ | 只存用途画像，不存调用契约——避免 schema 两份、避免过期 |

---

## 二、一个比喻：通讯录与派工单

公司有一本**通讯录**，登记了全部 32 位技术人员（正式员工 + 外包）。

- **通讯录本身一直都在**，不会因为某次派工而消失
- 客户提需求时，调度员**先翻完整通讯录**，挑出最匹配的 5 个人，**只把名字抄在派工单上**
- 拿到名字后，再按名字**回查通讯录**取到完整信息（电话、技能、报价），才真正联系

**派工单上的 5 个名字 ≠ 公司只有 5 个人**。同理，召回出的 5 个工具名 ≠ 系统只有 5 个工具。

代码里的对应关系：

| 比喻 | 代码里的东西 |
|---|---|
| 正式员工（工位在旁边） | 本地工具 `CalculatorTool` / `DataQueryTool`（有实例，直接调） |
| 外包团队（发工单联系） | MCP 子进程里的工具（只有目录描述，要连了才能用） |
| 通讯录 | `ToolRegistry._tools` + `gateway._tool_index` |
| 派工单上的名字 | `ToolHit.name`（召回结果） |
| 按名字回查取详情 | `get_tool(name)` / `ensure_registered(registry, names)` |

## 三、两条独立的线

```
【权威源：全量，一直都在】
  ToolRegistry._tools        本地工具实例（calculator / data_query ...）
  gateway._tool_index        远程工具目录 dict（web_search ... 含完整 inputSchema）
        |
        |  router.route() 每轮先把两者合并成 pool（全量候选池）
        v
     pool = {名字: 工具对象 或 目录条目}      <- 全量，比如 32 个
        |
        |  语义召回只在这里挑名字
        v
     rag_hits = ["weather", "web_search"]     <- 只有名字，比如 2 个
        |
        |  按名字回查权威源，取回完整对象
        v
     ensure_registered() -> MCPToolAdapter -> registry.register()
        |
        v
     get_openai_tools_schema(allowed=[...])   <- 只导出这几个的完整 schema 给 LLM
```

关键点：**向下走的每一步都是"名字"，取回本体靠回查**。索引从头到尾没参与"提供工具"。

## 四、全量候选池是怎么建的（每轮都建）

```python
# router.py:159-181
pool: Dict[str, object] = {}        # 工具名 -> 工具对象（本地）或目录条目（远程）
pool_names: List[str] = []

for tool in (registry.list_tools() if registry else []):     # ① 本地全量
    name = getattr(tool, "name", "")
    if name and name not in pool:
        pool[name] = tool
        pool_names.append(name)

remote_catalog = []
if self.gateway:
    try:
        remote_catalog = self.gateway.catalog()               # ② 远程目录全量
    except Exception as e:
        _logger.warning(f"网关目录读取失败，本轮只按本地工具路由: {e}")
for entry in remote_catalog:
    name = entry.get("name", "")
    if name and name not in pool:
        pool[name] = entry                                   # 目录条目进池
        pool_names.append(name)

if self.tool_index:
    self.tool_index.index_tools([pool[n] for n in pool_names])   # ③ 增量建索引
```

三点要留意：

1. **顺序很重要**：先有全量 `pool`，才拿它去建索引、才拿它去召回。所以召回永远是在全量里挑。
2. **本地优先**：`if name and name not in pool` 保证同名时本地工具不被远程覆盖。
3. **网关挂了不致命**：168-170 行 `try/except` 包住，目录读失败就退化为「只按本地工具路由」。
4. **增量索引**：181 行 `index_tools` 内部会跳过「文本没变且已编码」的工具（tool_rag.py:96-98），不会每轮重复调 embedding。

## 五、召回结果还要过一道校验

```python
# router.py:208-213
rag_hits: List[str] = []
if self.tool_index:
    for hit in self.tool_index.recall(query, top_k=self.top_k):
        if hit.name in pool and hit.name not in scores:      # <- 必须在全量池里
            rag_hits.append(hit.name)
            scores[hit.name] = hit.score
```

`hit.name in pool` 这道判断是**防御性**的：万一索引里残留了已下线的工具（索引比目录旧），召回出来也会被丢弃，不会往下传。

`scores` 里已有的名字跳过（211 行），是为了让**技能强绑定的工具**（分数 1.0）不被语义召回重复覆盖。

## 七、名字怎么变回「能用的工具」

### 7.1 触发点：名单定下来之后

```python
# router.py:244-245
if self.gateway and registry is not None:
    self.gateway.ensure_registered(registry, truncated)
```

### 7.2 `ensure_registered` 内部做了三件事

```python
# gateway.py:238-262
def ensure_registered(self, registry, names: List[str]) -> List[str]:
    if registry is None or not names:
        return []
    from modules.mcp.mcp_client import MCPToolAdapter
    newly: List[str] = []
    for name in names:
        if name in self._registered:            # 已注册过就跳过
            continue
        entry = self._tool_index.get(name)      # ① 从目录取回完整 info（含 inputSchema）
        if not entry:
            continue
        server = entry["server"]
        client = self._connect(server)          # ② 这时才真正起子进程
        if client is None:
            continue
        try:
            registry.register(MCPToolAdapter(client, entry["info"]))   # ③ 包装并注册
            self._registered.add(name)
            newly.append(name)
        except Exception as e:
            _logger.warning(f"MCP 工具注册失败: {name} | {e}")
    ...
```

三个关键点：

| 点 | 说明 |
|---|---|
| 完整信息从 `_tool_index` 回查 | 不是从 Tool-RAG 索引里来——索引里只有名字和向量 |
| **此刻才连 server** | 只有被召回的远程工具才起子进程，没被召回的一个都不起（懒加载） |
| 注册后与本地工具同构 | 之后统一走 `registry.get_tool(name)` / `execute_tool(name)`，Agent 分不清本地还是远程 |

### 7.3 React 循环里按名单过滤并导出 schema

```python
# react_agent.py:338-351
selected = [
    t for t in self.tool_registry.list_tools()
    if t.name in state.routed_tools
]
allowed = self._allowed_tools(state.principal, selected)
tools_schema = self.tool_registry.get_openai_tools_schema(
    user_level=user_level, allowed=allowed
)
```

`get_openai_tools_schema` 会生成完整 JSON Schema（参数、类型、描述）——**这份完整契约是从 registry 里的工具对象取的**，跟召回阶段那几个名字无关。

日志里这句能直接看出全量与本轮的关系：

```
本轮工具名单 5/5 个（候选池 32）: weather、web_search、...
```

`候选池 32` = 全量工具数（`decision.pool_size`，router.py:254），`5` = 本轮挑出来的。

## 八、三种「获取全部工具」的诉求，对应三种做法

| 你想干什么 | 正确做法 | 说明 |
|---|---|---|
| **列出全部**（调试 / 管理界面） | `registry.list_tools()` + `gateway.catalog()` | 两者合并即全量；索引（Tool-RAG）不能用于列举 |
| **让模型看到全部** | 启动时把网关目录**全量注册**进 registry，且不做路由过滤 | 早期 `main.py:111-113` 的循环注册就是这么干的 |
| **某个没被召回的工具也要能用** | 走**技能强绑定**或**默认工具兜底** | 分数 1.0 / `default_tools` |

### 一个容易踩的坑

**单纯把 `TOOL_RAG_ENABLED` 关掉，并不会变成"全量暴露"。**

因为 `tool_index=None` 后：

```
209 行  if self.tool_index:  → 不成立，rag_hits 为空
218 行  if not truncated:    → 成立，落到 default_tools 兜底
```

名单**反而更小**（只剩默认工具）。真正的全量需要在启动时 eager 注册所有远程工具，并让 `react_agent` 走 `router=None` 的分支（`react_agent.py:319`：`selected = self.tool_registry.list_tools()`）。

## 九、为什么索引里不存工具本体

`tool_rag.py` 开头的设计说明（14-18 行）写得很清楚：

```
【索引里存什么 / 不存什么】
    存：工具名 + 描述 + 参数名（用途画像，用于算相似度）
    不存：完整 JSON Schema（那是调用契约，留在 ToolRegistry，按需取用）
    把调用契约也塞进向量库，等于把「怎么调」和「该不该调」混在一起，
    既浪费索引空间，也让召回结果里混入参数噪声。
```

这样设计带来的三个好处，正好回答本文的问题：

1. **索引轻**：只存几十条向量，建得快、检索快
2. **权威源单一**：完整 schema 只在 registry / 目录里有一份，**不存在"索引里的定义过期了"这类问题**
3. **召回与取用解耦**：召回输出永远只是名字，取用时回查拿到的**一定是最新的**完整定义

## 十、漏召了怎么办（三道兜底）

| 兜底 | 位置 | 机制 |
|---|---|---|
| `min_score` 过滤 | tool_rag.py:194 | 宁可召回为空，也不塞无关候选进 prompt |
| 默认工具回退 | router.py:218-221 | 召回为空时用 `default_tools` |
| 技能强绑定 | router.py:200-206 | 绑定的工具分数 1.0，**不依赖召回** |

所以即便语义召回完全失灵，系统也不会「没有工具可用」，只是退回到少数几个默认工具 + 技能绑定工具。

## 十一、常见误解 Q&A

**Q：召回只给 5 个，那剩下的 27 个工具是不是就丢了？**
不是。它们一直在 `ToolRegistry` 和网关目录里，只是**这一轮没进 prompt**。下一轮换个问法，可能就是另一批 5 个。

**Q：能不能把全部工具都注册进 registry，反正也不占地方？**
技术上可以（就是早期做法），但会失去「按需连接」的好处：远程工具**每个都要起一个子进程**，全量注册意味着启动时就把所有 MCP Server 全部拉起来。这正是 Tool-RAG 要解决的技能膨胀问题。

**Q：索引和目录会不会不一致？**
可能（索引建完、目录中途变了）。所以 211 行有 `hit.name in pool` 校验，取用时也从 `_tool_index`（目录）而非 Tool-RAG 索引取完整信息，双重保险。

**Q：远程工具被召回后，下次还要重新连吗？**
不用。`gateway._registered`（245 行）记录了已注册的名字，`ensure_registered` 开头 `if name in self._registered: continue` 直接跳过。

**Q：`pool_size` 和日志里的"候选池"是什么关系？**
是同一个东西。`router.py:254` 把 `len(pool_names)` 放进 `RoutingDecision.pool_size`，`react_agent.py:344` 打印出来。它就是你系统里**全量工具的数量**，可以用来核对召回覆盖是否合理。

## 十二、一句话总结

1. **全部工具一直在**：`ToolRegistry`（本地实例）+ `gateway._tool_index`（远程目录），路由器每轮先合并成全量 `pool`。
2. **召回只输出名字**（`ToolHit.name`），且必须 `hit.name in pool` 才有效——它是在全量里筛选，不是替代全量。
3. **取回本体靠回查**：本地 `get_tool(name)`；远程 `ensure_registered()` → 从目录取完整 info → 连 server → 包 `MCPToolAdapter` 注册进 registry。
4. **索引只存画像不存 schema**，所以不存在「索引里的定义过期」问题，召回与取用彻底解耦。
5. **想让模型看到全部**，不是关 `TOOL_RAG_ENABLED`，而是启动时全量注册远程工具且不做路由过滤。
6. 日志里的「候选池 N」就是全量工具数，可用来核对本轮召回的覆盖情况。
