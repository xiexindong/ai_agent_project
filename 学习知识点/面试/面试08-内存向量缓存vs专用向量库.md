# 面试08：工具/技能向量为什么不进 Milvus，自己算余弦？

> 配套代码：`modules/tools/tool_rag.py:63-68、197-202、309-318`、`modules/skills/skill_registry.py:109`（`_vec_cache`）、`modules/rag/vector_store.py`（对照组：Milvus 用法）
> 一句话结论：**量级决定选型——工具和技能只有几个到几十个，字典遍历余弦是微秒级、零依赖；Milvus 的价值从"万级向量"才开始，为几个工具引入一个常驻数据库服务是负收益。**

---

## 一、先说结论

| 面试问 | 一句话答 |
|---|---|
| 为什么自己算？ | 向量总量 < 100 条，全量算余弦 O(N) 也就几十次乘加，微秒级 |
| 为什么不进 Milvus？ | 省下的计算 < 引入的成本（部署、连接、索引构建、故障面） |
| 存哪？ | 进程内存字典：`tool_rag._vectors`、`skill_registry._vec_cache` |
| 什么时候必须换 Milvus？ | 向量数万级以上、或需要持久化/多进程共享/复杂过滤时 |
| Milvus 在本项目管什么？ | **RAG 知识库**（Milvus），与**记忆注入**（PG+pgvector）是 prompt 里并列的两栏，不能混称 |

## 二、大白话拆解：同一个项目里的三种向量方案

| | Tool-RAG / 技能路由 | 记忆（长期召回） | RAG（知识库） |
|---|---|---|---|
| 存储 | 进程内存 dict | PG 表 + pgvector 列 | Milvus 集合 |
| 检索 | 手写余弦全量算 | SQL `<=>` 算子 + ivfflat 索引 | ANN 索引（COSINE） |
| 向量量级 | 几个~几十个 | 每用户几百~几千条 | 万级~百万级 chunk |
| 数据归属 | 代码里定义的静态清单 | 用户产生的动态数据 | 文档切分的产品数据 |
| 生命周期 | 随进程 | 随用户（90 天归档） | 随文档版本 |

## 三、输入 → 输出对照

```python
# Tool-RAG 召回（tool_rag.py:63 参数）
ToolRAG(top_k=5, min_score=0.25)
recall("今天北京天气怎么样")
# 内部过程: query 向量 × 每个工具向量，逐个算余弦 → 排序 → 0.25 过滤 → 截前 5
# 输出: [ToolHit("city_weather", 0.63), ToolHit("web_search", 0.41)]
#        （0.41 >= 0.25 留下；若还有个 0.19 的无关工具被过滤掉）

# 量级对比（为什么够用）：
#   10 个工具 × 1024 维 = 10 次点积 ≈ 万次浮点乘加 → 亚毫秒
#   10 万个 chunk × 1024 维 = 1 亿次浮点乘加 → 秒级，必须 ANN 索引（Milvus 的主场）
```

## 四、为什么要这么写

| 做法 | 原因（不这么写会怎样） |
|---|---|
| 向量存进程内存 dict | 进 Milvus：多一个常驻服务要部署、要探活、要建索引；工具清单是代码定义的静态数据，进程重启跟着代码重建，天然一致 |
| embedding 结果缓存（`_vec_cache` 懒加载） | 不缓存：每次路由都调一次 embedding API，白花钱加几百 ms 延迟 |
| 余弦手写（tool_rag.py:309） | 引 numpy/scipy 为 10 个向量算余弦：依赖与启动开销远超收益 |
| 工具画像变化时清缓存（register 重名 L128） | 不清：路由永远用旧向量，改了工具描述模型却按旧画像召回 |
| RAG 走 Milvus 不走内存 | 知识库 chunk 万级起步，全量算余弦秒级延迟；Milvus 的 ANN 索引把它压到毫秒 |
| 记忆走 PG+pgvector 不走 Milvus | 记忆要跟会话/用户数据一起事务管理（归档、删除、user_id 过滤），PG 一条 SQL 全办了；拆到 Milvus 要维护双库一致性 |

## 五、量级分界线（面试可直接背）

| 向量数 | 推荐方案 | 理由 |
|---|---|---|
| < 100 | 内存 dict + 全量余弦 | O(N) 就是几十次乘加，任何外部依赖都是负收益 |
| 1 千 ~ 10 万 | PG + pgvector（ivfflat 索引） | 与业务数据同库，事务一致，SQL `<=>` 算子够快 |
| > 10 万 / 多集合 / 复杂过滤 | Milvus 等专用向量库 | ANN 索引 + 分布式 + 标量过滤才是它的主场 |

本项目恰好三种量级各得其所：工具/技能（个位数，内存）、记忆（千级，PG）、知识库（万级，Milvus）。

---

## 六、简单总结

1. 选型看**量级**不看技术时髦度：工具/技能几个向量 → 内存 dict 手写余弦（tool_rag.py:309）；记忆千级 → PG pgvector；知识库万级 → Milvus
2. 三个数字：Tool-RAG **top_k=5、min_score=0.25**（tool_rag.py:63）；向量缓存懒加载一次后复用
3. 术语红线：**记忆注入（PG+pgvector）≠ RAG（Milvus）**，两者在 prompt 里是并列两栏（`## 知识库参考` 与 `## 历史记忆`），面试混称直接扣分
