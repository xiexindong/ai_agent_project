# 面试04：Skill 上百个且功能相近，怎么提升选择命中率？

> 配套代码：`modules/skills/skill_registry.py:173-383`、`config.py:129-135`
> 一句话结论：**命中率不是靠一个更聪明的模型，而是靠「三级漏斗」——L1 关键词免费砍掉绝大多数 → L2 向量只在剩余候选里精判 → L3 LLM 只看前 3 个候选的名字做最终分类；每一级的输入都是上一级砍过的候选池，成本逐级加码。**

---

## 一、先说结论

| 面试问 | 一句话答 |
|---|---|
| 上百个技能怎么选？ | 三级串行漏斗，不是全量向量召回，更不是全丢给 LLM |
| L1 为什么能砍掉大多数？ | 技能是人工定义的，触发词写得准；短语命中 0.6 分，≥0.6 直接定案 |
| 功能相近怎么区分？ | L2 向量看语义 + L3 只在「前 3 个候选」里让 LLM 二选一/三选一 |
| 候选池多大会撑爆？ | L2 只算 L1 候选前 N（skill_vector_top_n=3），L3 同样只看 3 个名字 |
| LLM 选错了怎么办？ | 强制 JSON 输出 + 校验技能名真实存在（防幻觉）+ 置信度 ≥ 0.5 才绑定 |

## 二、大白话拆解：三级漏斗全景

```
用户提问（100 个技能在册）
   |
   +- L1 关键词路由（零成本，全量扫）        skill_registry.py:173
   |     短语命中 0.6 / 双字词 0.4 / 单字 0.15，累加封顶 1.0
   |        score >= 0.6  → 命中，结束（绝大多数明确提问死在这里）
   |        score <  0.1  → 判无关，走通用对话
   |        0.1 ~ 0.6     → 模糊地带，带着候选下沉 L2
   |
   +- L2 向量语义路由（1 次 embedding）      skill_registry.py:223
   |     只对 L1 候选的前 3 个算余弦
   |        sim >= 0.75 → 命中，结束
   |        否则        → 下沉 L3
   |
   +- L3 LLM 兜底（1 次 LLM 调用）           skill_registry.py:282
         只把 3 个候选的【名字清单】丢给模型分类
         强制 JSON 输出 + 名字真实性校验 + confidence >= 0.5
```

| 部分 | 大白话解释 |
|---|---|
| `_route_keyword` | 给每个技能算"触发词命中得分"，像收银台扫码：码对上了直接过闸 |
| `score >= 0.6` 命中 | 触发词短语命中的权重 0.6——一个问题命中一个短语基本就是它了 |
| `_route_vector` | 语义复读机：换说法（"报销"vs"费用核销"）关键词对不上，向量对得上 |
| `skill_vector_top_n=3` | L2/L3 都只看前 3 个候选：候选池越大，越像两个相近技能的"二选一" |
| `_route_llm` | 终审法官：只判"A 还是 B 还是 C"，不看全文——问题小，答案就准 |
| 名字真实性校验 | 模型答了清单外的名字直接判无效（skill_registry.py:337），防幻觉 |
| `confidence >= 0.5` | 法官自己都没把握就不绑技能，回退通用对话（宁缺毋错） |

## 三、输入 → 输出对照

```python
# 场景1：明确提问（死在 L1，零 embedding 零 LLM 成本）
match("帮我按报销流程提交发票")
# L1: "报销流程" 短语命中 → score=0.6+ → hit
# 输出: SkillMatch(name="expense_reimburse")     ← L2/L3 未执行

# 场景2：换说法（L1 模糊，L2 定案，1 次 embedding）
match("出差垫的钱怎么核销")
# L1: 无触发词短语命中，双字词零星 → score=0.15 → 模糊，带 3 个候选下沉
# L2: "费用核销" vs expense_reimburse 的 routing_text → sim=0.78 >= 0.75 → hit
# 输出: SkillMatch(name="expense_reimburse")     ← L3 未执行

# 场景3：完全无关
match("今天天气怎么样")
# L1: 所有技能 score < 0.1 → miss
# 输出: None（走通用对话，L2/L3 都不执行）
```

## 四、为什么要这么写

| 做法 | 原因（不这么写会怎样） |
|---|---|
| 串行漏斗而非并行投票 | 并行 = 每问一句话都付 1 次 embedding + 1 次 LLM；串行让 80%+ 的提问死在免费的 L1 |
| L1 用「人工触发词」而不用自动画像 | 技能是人工定义的 SOP，触发词就是作者对"什么问题该走这套流程"的表态，比机器猜的准 |
| L2/L3 只看前 3 个候选 | 全量向量算 100 个：100 次 embedding 缓存查询 + 排序；候选砍到 3 个后相近技能才真正"可比" |
| L3 只给名字清单 | 给全文 = 一次 LLM 调用塞 100 段 SOP，prompt 爆炸且注意力被稀释，选错率反升 |
| 名字真实性校验 | 不校验：模型幻觉出 "expense_report"（不存在），后续 build_skill_context 拿 None 还要兜异常 |
| confidence < 0.5 放弃绑定 | 强行绑错 SOP = 整轮对话按错误流程走；不绑只损失"技能加成"，通用对话还能兜住 |
| 误判代价导向（单选） | 技能注入的是整段 SOP，选错带偏全轮；工具选错只是多试一次（详见面试06 的对比表） |

## 五、命中即停的主入口（skill_registry.py:360-383）

```python
def match(self, query, query_emb=None):
    decision, candidates = self._route_keyword(query)   # L1 先跑
    if decision == "hit":  return candidates[0]         # 命中 → L2/L3 不执行
    if decision == "miss": return None                  # 无关 → 直接结束
    m = self._route_vector(query, candidates, query_emb)  # 只有"模糊"才到这
    if m: return m                                      # L2 命中 → L3 不执行
    m = self._route_llm(query, candidates)              # 只有 L2 也没定才到这
    return m if m and m.confidence >= 0.5 else None
```

## 六、简单总结

1. 命中率的答案是**漏斗不是大脑**：L1 关键词（免费，短语 0.6 分）砍掉绝大多数 → L2 向量（1 次 embedding）精判 → L3 LLM（只看 3 个名字）终审
2. 三个关键数字：阈值 **0.6/0.1**（L1 高低双阈值）、**0.75**（L2 向量）、**0.5**（L3 置信度），全部在 config.py:129-135 可调
3. 防幻觉双保险：**强制 JSON + 名字真实性校验**；没把握（<0.5）宁可不绑技能——选错 SOP 的代价比不选大得多
