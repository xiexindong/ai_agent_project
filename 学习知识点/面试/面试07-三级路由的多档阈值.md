# 面试07：为什么设 0.6 / 0.1 / 0.75 / 0.5 四档阈值，而不是一刀切？

> 配套代码：`modules/skills/skill_registry.py:173-356`（L1/L2/L3 三级路由）、`modules/skills/skill_registry.py:360-383`（match 主入口）、`modules/agent/router.py:212-224`（上游复用匹配结果的三级 elif 链）、`config.py:129-135`
> 一句话结论：**多档阈值的本质是"分层置信度"——高阈值以上敢直接定案（省钱），低阈值以下敢直接放弃（省钱），中间的模糊地带才花钱升级判定；一刀切阈值没有"放弃"出口，所有问题都要付满全链路成本。**

---

## 零、先扫盲：本文会用到的术语（大白话版）

| 术语 | 大白话解释 |
|---|---|
| 阈值 | 一条"分数线"。分数过了线就放行，不过就拦截。四级阈值 = 四条不同用途的分数线 |
| L1 / L2 / L3 | 三级路由的三道关卡：L1 关键词（免费）、L2 向量（花一次 embedding 的钱）、L3 LLM（花一次模型调用的钱） |
| 分层置信度 | 像看病分诊：典型症状（高分）护士站直接处理，明显不相关（低分）直接劝退，拿不准的才逐级转诊到更贵的检查 |
| embedding | 把一句话翻译成一串数字（语义坐标），算一次要调外部 API，有延迟和费用 |
| 置信度（confidence） | L3 里 LLM 自己报的"把握有多大"，0~1。0.5 以下等于"我一半一半" |
| 模糊地带 | L1 得分卡在 0.1~0.6 之间的区间：关键词证据不足以下结论，又不甘心直接放弃 |

## 一、先说结论：四档阈值各管什么

| 阈值 | 值 | 在哪一级 | 管什么 |
|---|---|---|---|
| skill_high_threshold | 0.6 | L1 关键词 | 得分 ≥ 它：直接命中，后面全不跑 |
| skill_low_threshold | 0.1 | L1 关键词 | 得分 < 它：直接判无关，走通用对话 |
| （两档之间） | 0.1~0.6 | L1 → L2 | 模糊地带：候选下沉向量精判 |
| skill_vector_threshold | 0.75 | L2 向量 | 相似度 ≥ 它：命中 |
| skill_llm_confidence | 0.5 | L3 LLM | 置信度 ≥ 它才绑定，否则不绑 |

整条漏斗的文字流程图：

```
用户提问
   │
   ▼
L1 关键词打分（零成本）
   │  ≥ 0.6 ────────────→ 【命中】结束（一分钱没花）
   │  < 0.1 ────────────→ 【放弃】走通用对话（一分钱没花）
   │  0.1 ≤ 分 < 0.6 ───→ 下沉 ↓（花 L2 的钱）
   ▼
L2 向量精判（1 次 embedding）
   │  相似度 ≥ 0.75 ────→ 【命中】结束
   │  < 0.75 ───────────→ 下沉 ↓（花 L3 的钱）
   ▼
L3 LLM 兜底（1 次模型调用）
   │  confidence ≥ 0.5 ─→ 【命中】
   │  < 0.5 ────────────→ 【放弃】走通用对话
```

## 二、大白话拆解：每档阈值挡住什么

```python
# skill_registry.py:188-199（L1 双阈值裁决）
if best.score >= self._high:    # 0.6
    return "hit", candidates    # 敢定案：一个触发短语就值 0.6 分，命中即真
if best.score < self._low:      # 0.1
    return "miss", candidates   # 敢放弃：全表扫完连 0.1 都没有，问谁都白问

# skill_registry.py:254（L2 单阈值）
if sim >= self._vec_threshold:  # 0.75
    return m                    # 向量相似度 0.75：换说法也能到这个量级，可定案

# skill_registry.py:343-347（L3 置信度门槛）
if confidence < self._llm_confidence:   # 0.5
    return None                 # LLM 自己都说"五五开"，别绑——选错 SOP 比不选更糟
```

| 部分 | 大白话解释 |
|---|---|
| 高阈值 0.6 | L1 的"定案线"：触发词是人工写的，命中一个短语基本不会错 |
| 低阈值 0.1 | L1 的"淘汰线"：连零星单字（0.15/字）都没凑到，说明跟任何技能都不沾边 |
| 中间地带 | 最贵的区间：关键词说不清、向量还得看——只在这才付 embedding 的钱 |
| 0.75 | 向量"定案线"：0.75 以上是"换了个说法问同一件事"的典型量级 |
| 0.5 | LLM"信心线"：法官说"我觉得对半"等于没判，此时回退通用对话 |

## 三、输入 → 输出对照

```python
# 例1：得分落在高阈值之上（L1 定案，后两级不执行）
_route_keyword("帮我按报销流程提交发票")
# "报销流程" 短语命中 → best.score = 0.6
# 输出: ("hit", [...])          ← 0.6 >= 0.6，直接命中

# 例2：得分落在低阈值之下（L1 判无关）
_route_keyword("今天天气怎么样")
# 所有技能只匹配到零星单字 → best.score = 0.05
# 输出: ("miss", [...])         ← 0.05 < 0.1，直接放弃

# 例3：卡中间（花 L2 的钱）
_route_keyword("出差垫的钱怎么核销")
# 只有 "费用"/"核销" 零星双字词 → best.score = 0.4
# 输出: ("ambiguous", [3 个候选])  ← 0.1 <= 0.4 < 0.6，下沉 L2

# 例4：L3 置信度不足（不绑）
_route_llm("这个月部门开销走哪个口子", candidates)
# LLM 返回: {"skill": "expense_reimburse", "confidence": 0.4}
# 输出: None                    ← 0.4 < 0.5，宁可走通用对话
```

## 四、上游怎么复用匹配结果：router.py 的三级 elif 链

三级路由跑一次不便宜（最坏要一次 embedding + 一次 LLM），所以 AgentRouter 拿了结果就不再重算，按"代价从小到大"找现成结果（router.py:212-224）：

```python
skill, route, score = None, "", 0.0
if skill_match is not None:
    # 入口①：上游 prepare_state 已跑完三级路由，整个结果直接拿来用（零开销）
    skill, route, score = skill_match.skill, "prepared", getattr(skill_match, "score", 0.0)
elif skill_name and self.skill_registry:
    # 入口②：只有技能名字符串，字典反查实例（一次字典查找）
    skill = self.skill_registry.get_skill(skill_name)
    route = "prepared" if skill else ""
elif self.skill_registry:
    # 入口③：什么上游信息都没有，现场跑一次三级路由（最贵分支）
    m = self.skill_registry.match(query, query_emb=query_emb)
    if m:
        skill, route, score = m.skill, m.route, m.score
```

三个入口互斥：**能不重算就不重算**。注意 `query_emb` 也顺着传下去——上游算好的问句向量直接复用，又省一次 embedding。

| 入口 | 代价 | route 标记 |
|---|---|---|
| ① prepared（复用上游匹配结果） | 0 | `"prepared"` |
| ② 按名字反查 | 一次 dict 查找 | `"prepared"` / `""` |
| ③ 现场跑 match() | 最坏 = 关键词 + embedding + LLM | 真实层级 keyword/vector/llm |

## 五、关键设计对照表：为什么是这么写

| 做法 | 原因（不这么写会怎样） |
|---|---|
| L1 设高、低**两档**而不是一档 | 只有一档=没有"放弃"出口：无关问题也要走 L2 embedding + L3 LLM，全链路成本 ×100% |
| 高 0.6 低 0.1 差这么远 | 收太窄（如 0.4~0.5）：模糊带太窄会把"换个说法的真命中"错杀进 miss；收太宽（如 0.15~0.35）：什么问题都下沉，L1 省钱的意义没了 |
| L2 的 0.75 比 L1 的 0.6 严 | 向量分天生比关键词分"虚高"（语义空间的分数分布偏松），两个数字不可直接比，各定各的 |
| L3 置信度 0.5 是"及格线" | LLM 分类的置信度连一半都没有 = 跟抛硬币差不多；绑错 SOP 带偏整轮，不绑只损失加成 |
| 阈值全在 config.py 可调 | 写死在代码里换模型（embedding 分布变了）就要发版；配置化改环境变量即可（config.py:129-135） |

## 六、阈值调优的依据（面试加分项）

1. **看漏斗各层流量**：L1 hit 率长期 > 80% 说明触发词覆盖好；大量 ambiguous 说明触发词缺同义词
2. **换 embedding 模型必须重标**：分数分布是模型相关的（本项目用智谱 embedding-2，1024 维）
3. **宁可漏不要错**：技能单选场景下调高阈值会漏（损失加成），调低会错（带偏全轮）——漏的代价小，所以中间地带宁可下沉精判

## 七、面试追问（附回答要点）

**Q1：为什么 L1 要两个阈值，一个不行吗？**
要点：单阈值只有"过/不过"两个出口。设 0.6 单阈值：0.05 的无关问题和 0.4 的模糊问题都被判"不过"，但前者该直接放弃、后者值得升级判定——单阈值区分不了这两种情况，要么全放弃（漏掉换说法的真命中），要么全下沉（无关问题也付 embedding 钱）。双阈值给出了三个出口：定案 / 放弃 / 升级。

**Q2：L2 的 0.75 是怎么定的？**
要点：先承认它是经验值，再说依据：① 向量分数分布比关键词"松"，同义转述的典型量级在 0.75 以上；② 低于 0.75 的还有 L3 兜底，不会直接丢；③ 换 embedding 模型必须重新观察分布再调（配置化就是为了这个）。面试时强调"阈值是分布相关的，不是宇宙常数"。

**Q3：L3 为什么不直接信 LLM 的结果，还要看 confidence？**
要点：LLM 分类是"被迫作答"——prompt 要求必须输出一个 skill_name。如果没有置信度门槛，模型在"都不像"时也会硬挑一个（幻觉）。0.5 的意义是"比抛硬币强才采纳"；另外代码还校验了返回的技能名必须真实存在（skill_registry.py:337-342），名字不存在同样按未命中处理。

**Q4：三层都判不中怎么办？**
要点：返回 None，走通用助手流程（skill_registry.py:382-383）。技能是"软引导"不是硬门槛——没命中技能时模型照常回答，只是没有 SOP 加成。这比"硬绑一个不太对的技能"安全得多：绑错 SOP 会带偏整轮对话，不绑只损失一点流程规范性。

**Q5：阈值调错了会有什么症状？怎么发现？**
要点：高阈值调太高 → L1 hit 率暴跌、大量流量下沉 L2/L3，成本上升（看日志里各层命中分布）；低阈值调太高 → 真命中被错杀进 miss，用户抱怨"技能不生效"；L2 阈值调太低 → 误命中增多，回答风格被错误 SOP 带偏。发现手段就是 RouterDecision 的日志（router.py:303 每轮打一行"命中层级 + 分数"），按层级统计流量分布。

---

## 八、简单总结

1. 四档阈值 = **分层置信度**：0.6 以上敢定案、0.1 以下敢放弃、中间才花钱（embedding → LLM 逐级升级）
2. 双阈值的核心价值是**放弃出口**：一刀切没有 miss 通道，无关问题也要付满全链路成本
3. 三个边界：L2 0.75 比 L1 0.6 严是**分数分布不同**（向量分虚高）；L3 置信度 <0.5 不绑是**宁缺毋错**；阈值全部配置化（config.py:129-135）
