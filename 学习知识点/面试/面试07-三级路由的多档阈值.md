# 面试07：为什么设 0.6 / 0.1 / 0.75 / 0.5 四档阈值，而不是一刀切？

> 配套代码：`modules/skills/skill_registry.py:173-356`、`config.py:129-135`
> 一句话结论：**多档阈值的本质是"分层置信度"——高阈值以上敢直接定案（省钱），低阈值以下敢直接放弃（省钱），中间的模糊地带才花钱升级判定；一刀切阈值没有"放弃"出口，所有问题都要付满全链路成本。**

---

## 一、先说结论：四档阈值各管什么

| 阈值 | 值 | 在哪一级 | 管什么 |
|---|---|---|---|
| skill_high_threshold | 0.6 | L1 关键词 | 得分 ≥ 它：直接命中，后面全不跑 |
| skill_low_threshold | 0.1 | L1 关键词 | 得分 < 它：直接判无关，走通用对话 |
| （两档之间） | 0.1~0.6 | L1 → L2 | 模糊地带：候选下沉向量精判 |
| skill_vector_threshold | 0.75 | L2 向量 | 相似度 ≥ 它：命中 |
| skill_llm_confidence | 0.5 | L3 LLM | 置信度 ≥ 它才绑定，否则不绑 |

---

## 二、大白话拆解：每档阈值挡住什么

```python
# skill_registry.py:188-194（L1 双阈值裁决）
if best.score >= self._high:    # 0.6
    return "hit", candidates    # 敢定案：一个触发短语就值 0.6 分，命中即真
if best.score < self._low:      # 0.1
    return "miss", candidates   # 敢放弃：全表扫完连 0.1 都没有，问谁都白问

# skill_registry.py:254（L2 单阈值）
if sim >= self._vec_threshold:  # 0.75
    return m                    # 向量相似度 0.75：换说法也能到这个量级，可定案

# skill_registry.py:343（L3 置信度门槛）
if confidence < self._llm_confidence:   # 0.5
    return None                 # LLM 自己都说"五五开"，别绑——选错 SOP 比不选更糟
```

| 部分 | 大白话解释 |
|---|---|
| 高阈值 0.6 | L1 的"定案线"：触发词是人工写的，命中一个短语基本不会错 |
| 低阈值 0.1 | L1 的"淘汰线"：连零星单字（0.15/字）都没凑到，说明跟任何技能都不沾边 |
| 中间地带 | 最贵的区间：关键词说不清、向量还得看——只在这才付 embedding 的钱 |
| 0.75 | 向量"定案线"：0.75 以上是"换了个说法问同一件事"的典型量级 |
| 0.5 | LLM"信心线"：法官说"我觉得对半"等于没判，此时回退通用对话 |

## 三、输入 → 输出对照

```python
# 例1：得分落在高阈值之上（L1 定案，后两级不执行）
_route_keyword("帮我按报销流程提交发票")
# "报销流程" 短语命中 → best.score = 0.6
# 输出: ("hit", [...])          ← 0.6 >= 0.6，直接命中

# 例2：得分落在低阈值之下（L1 判无关）
_route_keyword("今天天气怎么样")
# 所有技能只匹配到零星单字 → best.score = 0.05
# 输出: ("miss", [...])         ← 0.05 < 0.1，直接放弃

# 例3：卡中间（花 L2 的钱）
_route_keyword("出差垫的钱怎么核销")
# 只有 "费用"/"核销" 零星双字词 → best.score = 0.4
# 输出: ("ambiguous", [3 个候选])  ← 0.1 <= 0.4 < 0.6，下沉 L2

# 例4：L3 置信度不足（不绑）
_route_llm("这个月部门开销走哪个口子", candidates)
# LLM 返回: {"skill": "expense_reimburse", "confidence": 0.4}
# 输出: None                    ← 0.4 < 0.5，宁可走通用对话
```

---

## 四、为什么要这么写

| 做法 | 原因（不这么写会怎样） |
|---|---|
| L1 设高、低**两档**而不是一档 | 只有一档=没有"放弃"出口：无关问题也要走 L2 embedding + L3 LLM，全链路成本 ×100% |
| 高 0.6 低 0.1 差这么远 | 收太窄（如 0.4~0.5）：模糊带太窄会把"换个说法的真命中"错杀进 miss；收太宽（如 0.15~0.35）：什么问题都下沉，L1 省钱的意义没了 |
| L2 的 0.75 比 L1 的 0.6 严 | 向量分天生比关键词分"虚高"（语义空间的分数分布偏松），两个数字不可直接比，各定各的 |
| L3 置信度 0.5 是"及格线" | LLM 分类的置信度连一半都没有 = 跟抛硬币差不多；绑错 SOP 带偏整轮，不绑只损失加成 |
| 阈值全在 config.py 可调 | 写死在代码里换模型（embedding 分布变了）就要发版；配置化改环境变量即可 |

---

## 五、阈值调优的依据（面试加分项）

1. **看漏斗各层流量**：L1 hit 率长期 > 80% 说明触发词覆盖好；大量 ambiguous 说明触发词缺同义词
2. **换 embedding 模型必须重标**：分数分布是模型相关的（本项目用智谱 embedding-2，1024 维）
3. **宁可漏不要错**：技能单选场景下调高阈值会漏（损失加成），调低会错（带偏全轮）——漏的代价小，所以中间地带宁可下沉精判

---

## 六、简单总结

1. 四档阈值 = **分层置信度**：0.6 以上敢定案、0.1 以下敢放弃、中间才花钱（embedding → LLM 逐级升级）
2. 双阈值的核心价值是**放弃出口**：一刀切没有 miss 通道，无关问题也要付满全链路成本
3. 三个边界：L2 0.75 比 L1 0.6 严是**分数分布不同**（向量分虚高）；L3 置信度 <0.5 不绑是**宁缺毋错**；阈值全部配置化（config.py:129-135）
